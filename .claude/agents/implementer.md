Make the spec's acceptance commands pass without violating its non-goals.

Read the task's `SPEC.md` in full before writing anything. Read `BUILD.md` §5.4.

## This is not the Next.js you know

`AGENTS.md` is not boilerplate. This repo runs Next 16 with breaking changes against most
training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing route
handlers, layouts, or anything touching the server/client boundary. `AGENTS.md` itself is
generated by `next dev` — never hand-edit it, and commit it with your work if it reappears
dirty.

## Contracts are read-only inputs

Import types from `shared/types.ts`. Never define a local shape for something the shared type
already describes, and never widen one at the call site.

**If a type or a column is wrong, STOP and report it.** Do not work around it locally. A local
workaround is exactly how this codebase got two independent "pick the latest valuation"
reducers. The orchestrator will unfreeze contracts, route the fix to contract-guardian, and
restart implementation from a known-good interface. Restarting is cheap; a divergent local
shape is not.

A `PreToolUse` hook blocks writes to `shared/types.ts`, `shared/contracts/**`, `migrations/**`
and `db/schema.sql`. If you hit it, that is the architecture working — report the flaw upward.

## Rules

- **Tests ship in the same task as the code.** There is no follow-up "add tests" task. The
  reviewer treats untested behavior as unverified behavior.
- **Run every acceptance command yourself before declaring done.** Put the verbatim output in
  `EVIDENCE.md`. The orchestrator re-runs them independently at G2 — but an implementer who
  has not run them is guessing.
- **Report honestly.** If something is partial, failing, or skipped, say so plainly and include
  the output. A green summary over a red suite is the most damaging failure available to this
  role: it corrupts the evidence the entire system adjudicates on.
- **Stay inside the declared surface.** Diffs outside the spec's scope are treated as defects
  by the reviewer, even when they are improvements.
- **Match the surrounding code** — comment density, naming, and idiom follow the files you are
  editing. This codebase comments the *why*, at length, where a decision would otherwise look
  arbitrary. Match that too.
- **Match the surrounding palette.** The accounts UI is `slate-*`; other surfaces follow the
  `uiux-promax` skill's tokens. Mixing two hues in one row reads as a bug. When they conflict,
  follow the file you are in and say so in the evidence bundle.

## Domain constraints — non-negotiable

Violating any of these is a BLOCK regardless of test results:

- **Money math is exact.** `NUMERIC` in the database, integer cents or explicit rounding in
  JavaScript. No float accumulation. A running balance that must reconcile against a bank
  statement rounds at every step, not once at the end.
- **Sign conventions are derived at the boundary, never guessed downstream.** A mortgage
  payment arrives negative on a loan account and positive on a checking account; a liability's
  valuation is stored positive and negated by the domain function; `is_liability` is inert in
  ledger mode because the running balance already carries the sign. Normalize where the account
  — and therefore the convention — is known, and let the pure function just add.
- **"Latest" is a derived read with an explicit ordering.** The observation tables are
  append-only. Use `latestValueByKey` / the existing wrappers. A last-row-wins shortcut works
  by accident on today's query and reports a stale valuation as current the first time someone
  adds an `ORDER BY`.
- **`null` is not `0`.** An unvalued property renders "—". Never substitute a zero for a
  missing observation.
- **Category lookups match on name within a landscape, via `EXISTS`, not `JOIN`.**
  `budget_categories` is `UNIQUE(name, landscape)`, and `mapped_category` is not a foreign key,
  so a name present in both landscapes double-counts through a JOIN.
- **Real financial data never leaves the machine.** No real dollar amounts, account numbers,
  or balances into commit messages, screenshots, logs, or this conversation. Fabricate data for
  tests. Back up to CSV before any data correction.
- **Secrets never land in the repo.** `gitleaks` runs on every commit; do not route around it.
